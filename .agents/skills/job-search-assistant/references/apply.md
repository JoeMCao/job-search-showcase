# Employer application

Work interactively on one role and one verified employer or ATS destination. Read its `ROLE.md` and the latest review packet. Keep fictional demo records offline. Stop on closed roles, a mismatched requisition, or evidence of a prior submission. For an uncertain prior attempt, reconcile the employer confirmation or candidate-provided receipt before further action.

## Prepare the form

Open the official application page and inspect the visible questions. Update the packet with the exact destination, proposed values, open questions, and the selected PDF revision. Candidate approval to draft a packet is separate from approval to send data to that site. Before typing candidate data into fields, uploading a PDF, or using a step that can save those details remotely, obtain the candidate's approval to prepare that specific application with those fields and file.

Use the supported browser interface to enter the approved values. Ask the candidate to handle sign-in, CAPTCHA, required personal declarations, and any file upload the browser can't perform. Have the candidate choose any optional demographic responses personally. Leave unknown answers open for them. If the site reveals new required questions or changes the proposed data, collect the new answers and approval before entering them. If a control may submit instead of advancing, stop for review. If the site or browser requires manual completion, hand off the exact site, PDF, answers, and remaining fields.

## Submit after review

Present the final fields, screening answers, recipient, exact résumé revision, and any declarations or consents tied to the submit button. Resolve all required fields. If a candidate upload cannot be verified in the browser, ask them to confirm the filename. Confirm the selected PDF hasn't changed since review. Wait for an explicit instruction to submit this exact, reviewed application, such as “Submit this application.” Treat approval as stale if the role, destination, fields, answers, declarations, or attachment changes. If the browser needs an additional permission or requires the candidate to perform the click, follow that flow.

Recheck `ROLE.md` for a prior attempt. Record `submission-uncertain` with the attempt time just before clicking Submit so an interrupted run can be reconciled. Submit once. Record `submitted` only after observing a confirmation page or candidate-provided receipt. Save the observed timestamp and receipt ID or confirmation text when available. If the result is unclear, leave it marked uncertain and report what happened. Check the confirmation or application history before considering a retry, and get fresh approval for any retry. For a manual handoff before any submit attempt, keep the role prepared and ask the candidate for the result if they submit it.
